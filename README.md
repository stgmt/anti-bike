# Anti-bike: не дать агенту написать велосипед

Гейт для агентов Claude Code, Codex, OMP и OpenCode. Ловит случай, когда агент собирается
написать то, что уже есть: свой кэш поверх готового, свой контейнер вместо `context_schema`,
свой фетч поверх `httpx`, свой параллельный представление вместо `asyncio.gather`.

Схема: `Stop`-хук получает транскрипт хода, `jscpd` отвечает фактом «такой код уже лежит в
файле X:строка», модель-классификатор отвечает «текст обещает новую сущность». Совпадение
двух ответов — блокировка с адресом.

## Почему не «просто прогнать jscpd»

Замеры на настоящей сессии (см. `reports/measurements.md`):

| Что подали | Позитив | Трудный негатив | Годится |
|---|---|---|---|
| Только jscpd | 0,027 | 0,069 | нет |
| Только список механизмов проекта | 0,975 | 0,020 | да |
| Оба | 0,942 | 0,032 | да, но jscpd не добавил |

Причина: клон в репо не говорит, родился он в этом ходе или лежал полгода. `jscpd --changed`
и `--baseline` отвечают именно на это: клон считается новым, если его не было в базовой ревизии.

## Что берём у jscpd

Свой детектор дублей не пишем. jscpd 5.4.2 умеет всё нужное:

- `--changed` — только файлы, которые git назвал изменёнными;
- `--baseline-from-ref` — сравнение с базовой ревизией, а не с прошлым прогоном;
- `--fail-on-new-clones` — код выхода по числу новых клонов;
- `--kind exact,renamed,gap` — отсечь дорогие виды клонов;
- `--reporters json` — машинный ответ с координатами обеих сторон;
- `--mcp` — проверка фрагмента без скачивания всего репо;
- `--similarity` — Type-3, похожие функции по нормализованному дереву;
- `--semantic` — Type-4 по эмбеддингам (548 МБ модель или API).

## Структура

```
src/
  intent.ts        разбор хода: есть ли обещание новой сущности
  clones.ts        вызов jscpd, разбор ответа в кандидатов
  context.ts       сборка списка готового: модули, версии, механизмы библиотек
  classify.ts      вызов модели-классификатора
  gate.ts          решение: пропустить, блокировать, чем
  metrics.ts       строки замеров в JSONL
test/
  *.test.ts        контракты: схемы, коды, границы
  fixtures/        ходы из настоящей сессии + синтетические клоны
reports/           замеры и разборы
```

## Порядок в хуке

1. Разобрать событие `Stop`: `last_assistant_message`, `transcript_path`, `stop_hook_active`.
2. Отсечь по тексту: нет обещания новой сущности — выйти, модель не звать.
3. Прогнать `jscpd --changed --baseline-from-ref <база>` по изменённым файлам.
4. Собрать список готового из репо: модули, версии, механизмы библиотек.
5. Позвать классификатор со списком и текстом хода.
6. Оба ответили «это велосипед» — вернуть `decision: block` с адресом `файл:строка`.
7. Записать замеры: что подали, что нашли, сколько заняло, что решили.

## Замеры, которые ведутся

Одна строка JSONL на ход:

```json
{"at":"2026-11-01T12:47:03Z","session":"5991cc66","asked":true,
 "files_changed":2,"clones_new":1,"clones_known":6,
 "ms":{"parse":4,"jscpd":96,"context":11,"model":1100},
 "facts":{"is_new_clone":true,"mechs":14},
 "verdict":"block","reason":"context_schema","false_positive":null}
```

## Что не делаем

- Своего детектора дублей.
- `PreToolUse`: замер показал 1,8–2,9 с на скан, это вешает каждую запись файла.
- Второго общего контейнера зависимостей в гейте.
