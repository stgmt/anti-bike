## 2. Настоящий велосипед

Блок `workSync` совпадает дословно в двух файлах:

```
createNativeProviderPorts.ts:40-53
createNativeProvisioningSupport.ts:30-42
```

```ts

      provider: 'claude';
    }): Promise<Record<string, unknown> | null>;
    buildRuntimeTurnSettledEnvironment(input: {
      provider: 'codex';
```

Направление доказывают даты добавления файлов:

| Файл | Добавлен | Коммит |
|---|---|---|
| `createNativeProviderPorts.ts` | 2026-10-30 18:15 | `1fa03bed4` |
| `createNativeProvisioningSupport.ts` | 2026-11-02 16:52 | `a008adf7b` |

Второй коммит добавил один файл, 78 строк, и в нём переписан этот блок.

**Почему это велосипед.** Готовый тип существовал, но был недоступен: интерфейс
`Dependencies` в `createNativeProviderPorts.ts:23` объявлен без `export`.
Скопировать было нечего, тип пришлось объявить заново. Правка на одну строку —
`export interface Dependencies`, — и импорт вместо копии.

У копии есть цена: два разных набора провайдеров (`'claude'` в первом методе,
`'codex'` во втором) при трёх провайдерах в домене
(`RuntimeTurnSettledProvider = 'claude' | 'codex' | 'opencode'`).

## 5. Что из прошлого отчёта не подтвердилось

Проверил заново, два утверждения были неверными.

**«Настройки по умолчанию не ловят велосипед».** Для этой сессии — ловят.
Пара `workSync` есть в дефолтном отчёте: 14 строк, 60 токенов. Я её сначала
пропустил, потому что мой же фильтр «только блоки с логикой» выбрасывает
объявления типов, а велосипед здесь именно объявление.

**«Нужны `--ignore-identifiers --ignore-literals --max-gap-lines 8
--similarity 0.6`».** Для известного велосипеда `renameWithRetrySync` эти
настройки не работают. Замер перебором:

| Порог похожести | Межфайловых находок |
|---|---|
| 0,40 | 1 (21 строка, 132 токена, нужная пара) |
| 0,41 | 0 |
| 0,50 | 0 |
| 0,60 | 0 |

Граница точная: 0,40 видит, 0,41 — уже нет. На 0,40 по всему `src/`
получается 89 925 находок за 35 секунд, то есть 71% строк помечены как
дубликаты. Это не сигнал.

## 6. Что из этого следует

Одни настройки на все случаи не закрывают задачу: порог, который ловит
переписанное тело, даёт мусор, а порог, который не даёт мусора, пропускает
переписанное тело.

Для этой сессии работают настройки по умолчанию и один фильтр, которого у меня
не было: **сторона пары должна быть файлом, изменённым в этой правке**. Замер:

- в `team-provisioning/main` 13 межфайловых совпадений с логикой;
- из них с сегодняшним файлом на одной стороне — **3**;
- все три оказались настоящими велосипедами из раздела 3;
- остальные 10 — между файлами от 30 октября и раньше, к этой сессии отношения
  не имеют.

Из 33 находок по умолчанию до трёх доходит за счёт двух отсевов: убрать
внутрифайловые (14) и убрать пары, где ни одна сторона не менялась сегодня.
Это дешёвая арифметика по списку изменённых файлов, без модели.

Случаи, где надо выносить общее из тела функции, отложены.

- **MCP на деле.** Проверял CLI. Как `check_duplication` отвечает агенту и

- **Сколько находок по умолчанию настоящие.** Три из трёх проверил чтением.
  Остальные 30 не читал; из них 14 внутрифайловые.
- **Что из 8 отобранных пар - настоящие велосипеды.** Проверено на одной паре

- **Фильтр по изменённым файлам на другом репозитории.** Мерил только здесь.
- **Хук на живой правке.** Мерил прогон по папке, не по одному файлу.
