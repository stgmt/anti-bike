resolveAnthropicRuntimeSelection — определяет профиль запуска модели Anthropic на основе каталога и возможностей рантайма, нормализуя уровни усилий и флаги fast mode.
reconcileAnthropicRuntimeSelections — согласовывает профили нескольких провайдеров для команды, объединяя их настройки усилий и режимов быстрого ответа.
getTeamEffortOptions — формирует массив опций для UI-селектора усилий, фильтруя их по поддержке каталога или рантайма с применением статических фоллбэков.
buildProviderPreparePlans — генерирует планы диагностики провайдеров, вычисляя сигнатуры запросов и ключи кэширования результатов проверки моделей.
storeShortLivedProviderPrepareModelResults — сохраняет результаты диагностики провайдеров во временный Map с автоматической очисткой устаревших записей по TTL.
canSkipPendingProviderDiscovery — оценивает состояние проверки готовности провайдеров, позволяя пропустить опциональный префлайт при зависании дисковера.
canResolveOpenCodeLaunchBlockers — анализирует список блокирующих ошибок запуска, определяя возможность их разрешения через scoped-подготовку среды OpenCode.
runProviderPrepareDiagnostics — выполняет асинхронную диагностику готовности провайдеров, агрегируя диагностические сообщения и обрабатывая специфичные ошибки ОС.
validatePrepareCwd — проверяет существование и тип рабочей директории перед запуском CLI-зондов, допуская graceful degradation для отсутствующих путей.
appendPreflightDebugLog — записывает структурированные события отладки префлайта в системный файл с предварительной маскировкой чувствительных данных.
resolveProviderCompatibilityModel — сопоставляет запрошенную модель с фактами рантайма, возвращая детерминированный статус совместимости или причину отказа.
isKnownAnthropicReasoningModel — идентифицирует поддерживаемые модели рассуждения Anthropic, игнорируя технические суффиксы версий в строковых идентификаторах.
normalizeEffortLevels — преобразует сырые строковые значения усилий в строгий набор Enum EffortLevel, отбрасывая неизвестные или пустые варианты.
hasAuthoritativeOpenCodeCatalogFallback — обеспечивает непрерывность запуска при ошибке обновления каталога, подменяя его данными из локальной scoped-подготовки.
